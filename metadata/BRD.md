## 文档目的

本 BRD 定义系统的**业务价值和用户需求**，由 Product Agent 维护。
所有需求必须有：
- 用户价值声明
- 业务场景支撑
- 优先级依据

---

## 一、项目愿景

### 1.1 核心价值主张

```
从论文公式 → 中文通俗解读 → 100%可执行代码成品
```

**用户痛点**：
- 论文公式晦涩难懂
- 代码实现与论文描述不一致
- 缺乏知识复用机制

**解决方案**：
- Agentic RAG 系统自动解读论文
- QA Agent 确保代码质量
- 问题追踪闭环保证持续改进

## 二、业务需求清单

### BR-001: QA Agent 双模型配置

**需求来源**: 用户反馈
**业务价值**: 高
**优先级**: P1

#### 用户场景

| 角色 | 场景 | 痛点 |
|------|------|------|
| 开发者 | 需要验证代码实现 | 规则工具无法检测逻辑错误 |
| 管理者 | 控制云端 API 成本 | 大模型调用费用高 |

#### 业务价值

| 价值维度 | 说明 |
|---------|------|
| 成本优化 | Code Review 用本地免费小模型 |
| 质量提升 | LLM 增强验证发现隐藏问题 |
| 灵活性 | 可切换云端/本地后端 |

#### 验收标准

| 标准 | 指标 |
|------|------|
| Code Review 能力 | 本地小模型可审查代码 |
| 默认云端验证 | 非 Code Review 任务用 glm-5 |
| 不影响现有流程 | validate() 方法保持不变 |

#### 关联文档

- FSD-QA-001 (功能规格)
- ADR-003 (架构决策)

---

### BR-002: 问题追踪闭环

**需求来源**: 质量管理要求
**业务价值**: 高
**优先级**: P1

#### 用户场景

| 角色 | 场景 | 痛点 |
|------|------|------|
| QA 工程师 | 发现问题后无追踪 | 问题被遗忘 |
| 开发工程师 | 修复无依据 | 不知道修复什么 |
| 项目经理 | 无法统计问题 | 没有质量指标 |

#### 业务价值

| 价值维度 | 说明 |
|---------|------|
| 可追溯 | 问题从发现到闭环全记录 |
| 可量化 | 问题数量、修复时间统计 |
| 可预防 | 预防措施防止问题复发 |

#### 验收标准

| 标准 | 指标 |
|------|------|
| 5项规范内容 | 背景、影响、根因、纠正、预防 |
| Agent 分工 | QA 发现 → Dev 修复 → Incident 监控 |
| 状态流转 | open → assigned → fixing → reviewing → closed |

#### 关联文档

- FSD-ISSUE-001 (功能规格)
- agent_governance.md (治理规则)

---

### BR-003: 透明度治理

**需求来源**: 企业合规要求
**业务价值**: 高
**优先级**: P0

#### 用户场景

| 角色 | 场景 | 痛点 |
|------|------|------|
| 合规专员 | 需审计 Agent 行为 | Agent 黑盒操作 |
| 安全团队 | 检测注入攻击 | 无法追踪攻击来源 |
| 数据团队 | 分析运行指标 | 缺乏统计数据 |

#### 业务价值

| 价值维度 | 说明 |
|---------|------|
| 可审计 | 14表审计日志全覆盖 |
| 可解释 | Agent 决策依据可说明 |
| 可追溯 | 问题根因可定位 |

#### 验收标准

| 标准 | 指标 |
|------|------|
| 审计覆盖率 | 100% 任务有审计 |
| 注入检测 | 5类攻击全部检测 |
| 指标监测 | 30+指标实时采集 |

#### 关联文档

- agent_governance.md (治理规则)
- governance_framework_design.md (框架设计)
