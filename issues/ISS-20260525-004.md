## 一、自查目标 (Background)

### 检查范围

所有与 LLM/RAG 交互后是否存在强制截断字符的情况：
1. 截断后给到 LLM 的信息
2. 截断后给到 RAG 的信息
3. 截断后输出给用户的信息

### 检查目的

确保信息完整性，防止因截断导致：
- LLM 收到不完整信息，生成错误解释
- 用户收到截断输出，缺失关键信息
- 审计日志记录截断版本而非完整版本

## 四、根因分析 (Root Cause)

### 根因类型

`design_limitation` - 设计时为控制Token/显示长度而截断

### 根因详情

| 根因 | 说明 |
|------|------|
| Token成本控制 | 截断减少输入Token，降低API成本 |
| 显示空间限制 | WebUI界面空间有限，需要截断显示 |
| 性能优化 | 长文本处理耗时，截断提高速度 |
| 未考虑完整性 | 设计时未明确"完整性优先"原则 |

### 5.2 修复代码设计

#### 修复 `_assemble_context()` (LLM输入完整性)

```python
def _assemble_context(self, chunks: List[Dict], mode: str = "full") -> str:
    """
    组装上下文 - 支持完整版和显示版
    
    Args:
        chunks: 论文片段列表
        mode: 'full' 完整版给LLM, 'display' 截断版给显示
    """
    parts = []
    for i, chunk in enumerate(chunks[:5]):
        content = chunk.get("content", chunk.get("text", ""))
        
        if mode == "full":
            # 完整版给LLM - 不截断
            parts.append(f"[{i+1}] (ID:{chunk['chunk_id']})\n{content}")
        else:
            # 显示版 - 智能截断（按段落边界）
            paragraphs = content.split("\n\n")
            truncated = paragraphs[0][:500]
            parts.append(f"[{i+1}] {truncated}...")
    
    # 审计记录完整版
    if mode == "full":
        self.audit.log_prompt(
            template="rag_context_full",
            assembled_prompt="\n\n".join(parts),
            metadata={"mode": "full", "chunks": len(chunks)}
        )
    
    return "\n\n---\n\n".join(parts)
```

#### 修复 `_generate_napkin_summary()` (审计完整)

```python
def _generate_napkin_summary(self, query: str, context: str) -> str:
    """
    生成餐巾纸摘要 - 完整版审计，截断版显示
    """
    # 完整版
    full_summary = self._extract_key_summary(context)  # 不截断
    
    # 审计记录完整版
    self.audit.log_output(
        formatted_output=full_summary,
        metadata={"type": "summary_full", "length": len(full_summary)}
    )
    
    # 显示版（智能截断）
    display_summary = full_summary[:200] + "..."
    
    return {
        "full": full_summary,      # 完整版（审计/API用）
        "display": display_summary  # 显示版（WebUI用）
    }
```
